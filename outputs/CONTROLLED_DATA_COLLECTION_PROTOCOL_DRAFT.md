# 受控物品配对数据采集流程（讨论草案）

> 状态：供导师/学校讨论的操作草案；不是伦理批准、招募通知或参与者同意书。未经学校要求的审批和书面同意，不得招募、拍摄、上传研究数据或调用 DeepSeek。

## 目的与范围

建立有可靠“同一件具体物品”正例的检索评估数据，比较 A) 表单信息排序、B) 加入照片结构化属性、C) 在前 K 名中加入候选照片直接比较。受控实验测量的是规定采集条件下的候选排序能力，不是现实失物找回率、物品所有权或参与者实际丢失物品的找回成功率。

## 需要导师/学校先决定

1. 是否需要伦理审查、由哪个委员会审批，以及审批编号和条件。
2. 参与者来源、人数、招募方式、报酬（如有）和退出机制。
3. 是否允许把图像和哪些字段发送给 DeepSeek；是否需独立选择加入及替代流程。
4. 图像、匿名映射表、标注、模型输出的存放位置、访问人员、保留期限和销毁方式。
5. 最小样本量与可接受的探索性研究定位；下方 pilot 数只是流程建议，不是统计功效结论。
6. 是否允许使用公开 CUTE 数据做补充视觉压力测试。维护者数据说明称 10,000 张，NeurIPS 论文称 18,000 张；本次只通过 HTTP Range 读取 ZIP64 目录和一张样例图，目录列出 17,804 个 JPEG，仍与两项官方公布数字不符，原因未查明。完整 ZIP 约 31.4 GB，未下载。它仅可用于冻结方法的外部同实例视觉压力测试，不作调参集，也不把它设为必要前提；使用前仍须导师/学校认可及核对 CC BY 4.0 署名和 API 处理安排。

## 采集设计候选

### 试采（仅审批完成后）

- 先用约 5–10 件非敏感日常物品检查拍摄流程、字段可理解性、图片质量和标注规则。
- 试采数据不自动并入最终测试集；若用来改提示词或排序规则，只能作为开发数据，或依导师批准方案排除。
- 记录物品因模糊、遮挡、反光、隐私内容或参与者撤回而被排除的原因。

### 正式样本建议

- 样本单位是**具体物品身份**，不是图片张数。一件物品对应一个随机 `item_group_id`；匿名的 `contributor_group_id` 可关联由同一贡献者提供的物品，用于分组；分析文件不出现姓名或可反查身份的代码。若没有可链接贡献者（例如独立采购物品），留空并记录限制。
- 样本量不在本草案中锁定。先用 pilot 的正例率、配对簇数、候选池设计和导师认可的主要指标，估计正式数据需求；物品簇较少时，bootstrap 区间应明确标为探索性。
- 尽量覆盖若干类别、颜色、纹理和尺寸。对每件物品安排不同背景、角度或照明，避免查询侧与候选侧只是同一张照片的复制或裁切。
- 预先规定拍摄条件组合和类别配额。纳入高相似但确为不同实物的同类别困难负例，不要只用类别完全不同的简单负例。

## 每件物品的记录步骤

1. 取得单独的研究参与同意；说明拍摄用途、可选的第三方 AI 处理、公开展示范围、退出方式和删除联系渠道。公开展示授权、研究使用授权、DeepSeek 处理授权分别记录，不用一个勾选代替全部授权。
2. 检查物品和取景画面。避免人脸、身份证件、银行卡、屏幕通知、地址标签、车牌、钥匙齿形/门禁码、病历及其他不必要的个人资料。无法安全移除时不拍摄并记录排除原因。
3. 给物品分配随机匿名 `item_group_id`；参与者同意记录及身份映射表与图像、CSV 分开存放，并限制访问。
4. 以两次独立拍摄产生查询侧和候选侧记录照片。重新摆放物品并改变背景或视角；记录拍摄条件代码，不保留精确 GPS、住宅地址或不必要的时间精度。不要复制第一张图作为第二张。
5. 按真实系统字段分别写一条 `lost` 与一条 `found` 记录，使用研究用的粗略地点和时间字段。若模拟地点/时间噪声，预先规定扰动规则并对所有方法一致应用，不按模型结果挑选。
6. 每件物品形成一对已知正例。物品身份由独立采集保管人依据 `item_group_id` 映射确认；模型输出和匹配分数不得用于创造 ground truth。
7. 负例来自不同 `item_group_id`。记录是否为同类别或近似颜色的困难负例；不能仅因视觉不相似就标为负例。
8. 两名标注者在不知道模型排名的情况下独立标注一部分或全部配对：`1` 同一具体物品、`0` 确认不同、`uncertain` 证据不足。报告一致性后再按预设规则裁决；普通标注者不接触参与者身份资料。

## 分组与防止泄漏

- 先锁定物品/贡献者分组，再划分 development/test。同一 `item_group_id` 的所有照片、lost/found 记录及派生分数只能进入同一 split；同一非空 `contributor_group_id` 也应尽可能整体留在同一 split。
- 若一位贡献者提供多件物品或共享拍摄背景，优先让其全部物品进入同一 split。若样本不足以按贡献者分组，至少评估这一泄漏风险并在论文披露。
- 测试集每个 lost 查询的候选池为同一 test split 的全部 found 记录；标签覆盖池内所有候选。未确认候选标为 `uncertain`，仍占据排序位置，不能静默删除或改成负例。
- 每条查询共用同一个冻结候选池，因此按查询物品组 bootstrap 的区间只描述给定该候选池时的查询间变异，不包含候选池重新抽样的不确定性。论文需限定结论范围；若研究目标是推广到其他候选池，应先由导师另定统计设计。
- 仅在 development 调整提示词、权重、阈值、图像缩放和候选 K。冻结后为 test 生成固定照片分数并运行最终评估；不得按 test 错误调参。

## DeepSeek 处理规则

- 只有学校/导师书面确认允许，且记录有单独第三方 AI 同意时，才上传图像；否则只运行方法 A 或获准的本地方法。
- 每次调用日志记录匿名 ID、模型 API 名称、提示词/预处理版本、UTC 时间、耗时、失败类别、输入/输出 token 和控制台实际费用；不得记 API key 或参与者身份。
- 视觉分数是排序信号，不是同物概率、身份识别或所有权结论。模型输出不得用于确认 ground truth。
- 未同意 AI 的图像只能参加获准的非视觉方法；不能用于视觉属性提取、照片比较或模型调试。

## 数据管理和删除

- 仅用匿名研究 ID 命名图像；身份映射表与 CSV/图像分开存放。不要把照片、映射表、同意表或可识别字段提交到 GitHub。
- 为研究文件设置访问控制和加密备份；仅获批研究人员可访问。研究数据保留期限遵循审批/同意文件，不直接套用应用的 90 天线上记录期限。
- 参与者撤回或发现意外敏感信息时，按批准流程暂停处理、隔离或删除相关图像、标签及派生视觉结果，并在受限审计记录中说明删除范围。若结果已匿名聚合而无法定位，须在同意材料和审批方案中预先说明。
- DeepSeek 等第三方有自己的处理与保留条款；审批前核对服务条款、处理地区和密钥权限，不承诺超出官方条款的删除能力。

## 数据文件与质量门槛

- 使用 `records_template.csv`、`annotation_round_template.csv`、`pair_labels_template.csv` 和 `experiment_log_template.csv`；照片留在受限目录，CSV 仅保存匿名图像 ID。
- 参与者说明和分项同意清单工作模板见 `PARTICIPANT_INFORMATION_AND_CONSENT_DRAFT.md`；须用学校正式格式替换、审查和批准后才可招募。DeepSeek 的处理地区与保留安排需在同意文本定稿前核实。
- 导入评估前，运行现有 `scripts/validate_dataset.py` 做结构检查，并人工核对图像映射、授权、物品身份和候选池完整性。脚本通过不等于 ground truth 正确或伦理获批。
- 在 development 固定 A/B/C 排序版本和统计方案；当前建议以 C 对 A 的 Hit Rate@5 差值作为唯一确认性主要比较，组件对比和 Recall@5、MRR@5 作为次要/探索性分析。该方案及区间/多重比较处理须在查看 test 结果前由导师确认。
- 采集不足、标签不确定、API 失败、退出/删除和排除记录均纳入流程图/实验日志，不能只报告成功样本。

## 完成后的产物

1. 去身份化图像与元数据清单；身份映射和同意记录单独受限保存。
2. 按物品及贡献者分组锁定的 development/test 划分。
3. 原始双人标注、分歧裁决记录和最终配对标签。
4. 冻结的模型/提示词/预处理记录、API 用量日志及 test 照片分数。
5. 数据预检和评估输出、错配人工复核结果及局限说明。
