# 研究与评估计划（草案）

> 这是供讨论和导师确认的研究方案，不代表学校已批准，也不锁定样本量或研究方法。

## 研究问题

**主要问题：** 与只使用表单信息相比，加入照片属性提取及候选照片直接比较，能否让真实的失物/拾获配对更常出现在前 5 个候选中？

**次要问题：** 哪些因素（类别、颜色、品牌、显著特征、地点或时间）对排序结果贡献最大？系统的排序耗时和每条记录的照片分析费用是多少？

## 比较方法

对同一批查询记录和候选记录运行以下方法：

1. **表单基线：** 使用用户填写的类别、颜色、地点、时间和说明，不使用照片分析结果。
2. **视觉属性方法：** 在表单信息上加入照片分析的类别、颜色、品牌（若清楚可见）和显著特征。
3. **照片比较方法：** 先用相同的属性方法筛出相同数量的候选，再让视觉模型直接比较查询照片和候选照片。

各方法应使用相同的查询、候选集合和标注答案。排序权重与模型提示词只用开发集调整；测试集不用于调参。第三种方法应先按第二种方法排序，再只比较前 K 个候选照片（默认 K=5），按照线上规则将启发式分数的 45% 与照片比较分数的 55% 合并。离线评估脚本通过 `photo_scores.csv` 导入预先生成的分数，不会在运行评估时调用 DeepSeek。

照片比较分数生成前需固定模型名称、提示词、图片预处理和日期，并按学校批准的数据流程处理图片。每个查询应按线上流程将查询照片和属性排序前 K 个候选放入同一多图请求，再按候选编号记录各分数。开发集可用于修订提示词；最终测试集的比较分数须在方案冻结后生成，不得根据标签调分。分数必须是模型对物品外观相似度的 0–100 参考值，不是概率或所有权判定。

## 数据集建议

- 先与导师确认数据来源、样本目标、研究伦理和保存期限，再收集或拍摄图片。
- 优先拍摄经物品所有者同意的普通物品；避免拍到人脸、证件、屏幕内容、地址标签或其他个人资料。
- 每个查询至少有一个人工确认的正确配对，并加入外观相似但不匹配的干扰项；记录哪些候选确认为负例，未确认的候选不要随意当成负例。
- 为每条记录保存匿名编号、失物/拾获方向、类别、粗略地点、时间范围、图片来源和人工配对标签。分析数据不保存姓名、电话号码或精确住址。
- 按“物品身份”划分开发集和测试集。同一件物品的照片、近重复照片和同一配对不能跨集合，避免数据泄漏。
- 样本量先作为导师讨论事项；可先做小型试标注，检查标注规则是否清楚，再据此估算正式数据规模。

## 评估指标

- **Hit Rate@5 / Recall@5（主指标）：** 查询的至少一个正确配对是否出现在前 5 名；若一条查询有多个正确配对，计算其中被找回的比例。
- **MRR@5（次指标）：** 正确配对越靠前，得分越高；前 5 名没有正确配对则记为 0。
- **运行指标：** 每种方法的中位响应时间、照片分析调用失败率，以及按实际 API 用量估算的单条记录费用。
- **易用性（可选）：** 在学校伦理许可和导师批准后，让参与者完成发布记录和判断候选结果的任务，记录完成情况并收集简短反馈。

报告每个指标的样本数、定义和不确定性；当前脚本提供按 `item_group_id` 重抽样的配对 cluster bootstrap 95% 置信区间，用来估计方法间 Hit Rate@K、Recall@K 和 MRR@K 的差值，以减少同一物品多条查询造成的相关性影响。区间不等于因果证明，物品组数量较少时应谨慎解释。不要只报告一个总体准确率，也不要把排序分数称为“匹配概率”。

当前离线评估脚本按查询计算 Hit Rate@K、Recall@K 和 MRR@K，再对查询取宏平均。当前候选池定义为 `records.csv` 中同一 split 的全部 `found` 记录；每条 `lost` 记录都是查询，必须在配对 CSV 中标注池内每个候选。高置信度 `0`/`1` 才计为已判定的负例/正例，而 `uncertain` 和低置信度候选仍参与排序并占据名次，不作为正例或负例计数。可降低置信度门槛做敏感性分析。若未判定候选实际上是正例，主指标可能偏保守；需报告这类候选数量和来源候选池覆盖范围。提供照片比较分数时，脚本会额外评估第三种方法，并导出逐候选名次、参考分、标签置信度、是否计入指标和匹配依据，以便分析错配。评估工具的存在不代表已有数据或实验结果。

模型调用耗时、返回 token、失败和费用的逐次记录模板见 [`EXPERIMENT_LOG_GUIDE.md`](EXPERIMENT_LOG_GUIDE.md) 与 [`experiment_log_template.csv`](experiment_log_template.csv)。模板目前为空；未获学校批准前不使用真实研究照片或参与者资料填表。

## 执行步骤

1. 与导师确定研究问题、伦理要求、数据规模和参与者安排。
2. 写出标注指南，并用少量图片试标；修订有歧义的类别、地点和时间定义。
3. 收集并匿名化图片与记录，建立开发集、测试集和人工配对标签。
4. 固定表单基线、视觉属性方法和照片比较流程；记录模型名称、提示词版本、日期、预处理和失败处理方式。
5. 在开发集生成候选照片比较分数并检查流程；冻结方案后，为测试集生成固定分数，再运行三种排序方法。
6. 计算排序指标、线上请求响应时间、失败率和实际 API 成本。离线排序脚本不测模型响应时间，因此要单独记录生成照片分数时的调用时间和失败情况。
7. 分析错误案例，例如相同颜色的物品、遮挡、模糊照片、品牌不可见、地点过大或时间范围重叠。
8. 若获批准，再做小规模可用性评估；汇总限制并写入论文。

## 主要研究风险

- **标注不确定：** 采用清晰的配对标准；记录无法确认的候选并排除或单独分析。
- **数据偏差：** 记录物品类别和拍摄条件；说明样本不能代表所有真实失物报告。
- **图片隐私：** 只收集研究所需信息，限制访问和保存时间；按学校要求取得同意并删除数据。
- **模型不稳定或费用变化：** 固定实验版本与提示词，保留不调用视觉 API 的基线，并记录实际用量。
- **过度声称效果：** 结果只说明在本数据集和设定下的排序表现，不证明物品属于某人，也不直接推断现实世界成功找回率。

- 是否需要伦理审批，以及可用的图片来源和同意流程。
