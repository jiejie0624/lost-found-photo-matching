# 数据集与配对标注指南（草案）

> 本文件用于准备离线匹配实验。收集真实图片或招募参与者前，先按学校和导师要求确认伦理审批、同意方式、保存位置和删除期限。

## 文件

- [`records_template.csv`](records_template.csv)：每条失物或拾获记录一行。
- [`pair_labels_template.csv`](pair_labels_template.csv)：每个“查询记录—候选记录”组合一行。
- [`photo_scores_template.csv`](photo_scores_template.csv)：第三种评估方法所需的候选照片直接比较分数。

CSV 只放匿名编号和粗略属性。不要把姓名、电话、账号、精确地址、证件内容或原始图片放进 CSV。图片应放在受限访问的独立位置，并使用随机图片编号关联。

## 记录字段

| 字段 | 填写规则 |
| --- | --- |
| `record_id` | 唯一匿名编号，例如 `R0001`；不要编码个人身份。 |
| `item_group_id` | 同一件实物的匿名编号；用于避免同一物品跨数据集泄漏。不同物品不能共用。 |
| `direction` | `lost` 或 `found`。 |
| `title` | 用户填写的简短物品标题。 |
| `category` | 用户从固定类别表选择的类别；无法判断时填 `unknown`。 |
| `color` | 用户填写的颜色，作为表单基线信息；未知时留空或填 `unknown`。 |
| `location_zone` | 统一的粗略地点区域编号或名称；不要写门牌、房间号或精确坐标。 |
| `time_start`, `time_end` | 可能遗失/拾获的时间范围，使用 ISO 日期时间；精度按研究需要，勿记录不必要的精确时间。 |
| `description` | 用户填写的说明；不要写个人信息或未公开的认领验证答案。 |
| `vision_category` | 视觉模型提取的物品类别；没有分析结果时留空。 |
| `vision_colors` | 视觉模型提取的颜色；多项用分号分隔；没有分析结果时留空。 |
| `vision_brand` | 视觉模型从图片中看清的品牌；看不清或没有分析时留空。 |
| `vision_features` | 视觉模型提取的可见特征；多项用分号分隔；不写推测或个人信息。 |
| `image_id` | 随机匿名图片编号；真实图像与编号的映射表应分开并限制访问。 |
| `image_consent` | `yes`、`no` 或 `not_applicable`；只有符合批准的同意流程才使用图片。 |
| `split` | `development` 或 `test`；以 `item_group_id` 为单位分组后填写。 |

类别表应与当前应用保持一致：`电子产品`、`证件与卡片`、`钥匙`、`包袋`、`衣物`、`水瓶与餐具`、`书籍文具`、`饰品`、`其他`。类别可以按导师反馈调整，但正式评估开始后不要随结果改类别。

## 配对标签

每行表示一个失物查询与一个拾获候选之间的判断。离线评估使用同一份配对集合，比较只用表单信息的基线与再加入 `vision_*` 属性的方法：

评估脚本把 `time_start` 与 `time_end` 的中点传给当前原型的单一时间匹配规则；若时间范围很宽，这只是近似，报告结果时应说明这一限制。

- `1`：有可靠依据确认是同一件实物。
- `0`：有可靠依据确认是不同实物。
- `uncertain`：证据不足或标注者意见不一致；不计入主指标，单独统计。

只因为类别、颜色、地点或时间相似，不能把一对记录标成 `1`。优先由了解实物来源的人确认；若无法确认，标成 `uncertain`。`label_confidence` 用 `high`、`medium`、`low`；评估脚本默认只纳入高置信度的 `0`/`1` 标签，可用 `--min-confidence medium` 做敏感性分析。

每个失物查询应配有至少一个确认的正例，并有外观相似但已确认不同的负例。未知候选不能自动当成负例。所有被评估的方法必须使用同一个候选集合。

## 候选照片比较分数

要评估第三种方法，可另建 `photo_scores.csv`，列为 `query_record_id,candidate_record_id,visual_score`。`visual_score` 是固定视觉模型对这对照片的 0–100 外观相似参考分，不是概率，也不能当作物品所有权证明。

只需给每个查询填写视觉属性方法排在前五名的候选照片分数；生成时应按线上方式把查询照片和这些候选照片放在同一多图请求中，并按候选编号保存模型返回的分数。脚本会验证这些候选都有分数，并按线上当前规则计算 `属性参考分 × 0.45 + 照片参考分 × 0.55` 后重新排序。模型、提示词、图片预处理和生成日期要留在单独的实验日志中。不同方法应使用相同候选集合和冻结的测试标签。

分数生成需遵循导师和学校批准的图片处理方案。若把研究图片发送到 DeepSeek 等第三方服务，必须先确认获准；不要把含有未经许可个人资料的图片直接用于 API 调用。照片分数 CSV 中仅放匿名记录编号和分数，不放图片、姓名或联系方式。

## 标注流程

1. 先用少量样本试标；两位标注者独立判断配对，并记录分歧原因。
2. 修订标签说明，明确哪些证据足以确认同一实物，再开始正式标注。
3. 正式数据至少对一部分配对双人独立标注；通过讨论或第三方裁决处理分歧，并报告一致性。
4. 保存标签、置信度、匿名标注者编号和简短理由；理由不要包含联系信息或认领用秘密细节。
5. 在运行系统前冻结测试标签；模型开发者不应根据测试集标签调整排序权重或提示词。

## 划分与隐私

- 按 `item_group_id` 分配开发集或测试集；同一件物品的多张照片、裁剪图和重复记录必须留在同一集合。
- 测试集只用于最终比较。类别权重、提示词和预处理规则在开发集确定后固定。
- 收集前说明用途、访问者、保存期限和退出/删除办法；未经批准，不要把真实数据上传到 GitHub、公开云盘或第三方 API。
- 上传给视觉 API 前，应确认学校批准和服务条款允许这种处理；移除 EXIF 不代表图片中不含隐私信息。
- 若意外收集到人脸、证件或其他敏感内容，按批准的处理流程删除或隔离，不要继续用于实验。

## 质量检查

正式评估前检查：编号唯一、必填字段齐全、时间范围有效、配对方向正确（`lost` 对 `found`）、同一物品没有跨集合、未知标签未被当成负例、测试标签已冻结、图片同意状态可追溯。

录入 CSV 后可运行 [`../scripts/validate_dataset.py`](../scripts/validate_dataset.py) 做结构预检。它会检查上述大部分机械条件，以及正例是否与同一 `item_group_id` 一致、负例是否来自不同实物。它不会判断人工标签是否正确，也无法知道是否漏掉研究方案所定义的候选项；逐查询核实固定候选集合仍是研究者的责任。

## 待导师确认

- 图片来源、参与者同意和伦理审批流程。
- 类别列表、时间精度、地点区域粒度和图片保存位置。
- 标注人数、一致性指标、低置信度标签处理及样本规模。
- 是否允许将图片发送至 DeepSeek API，以及如何说明第三方处理。
