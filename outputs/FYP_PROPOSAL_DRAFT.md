# FYP Proposal 草案

> 供学生与导师讨论的初稿。学校格式、正式伦理安排、数据规模和研究范围尚未确认。本文没有实验结果，也不预先声称系统有效。

## 暂定题目

**结合视觉属性与时空信息的失物配对系统**

## 摘要

失物与拾获记录通常包含物品照片、类别、地点和时间等线索。记录数量增加后，用户需要逐条浏览，可能错过外观相似且时空信息接近的候选。本项目拟开发一个适用于手机浏览器的响应式失物配对原型。用户提交失物或拾获记录后，系统可调用视觉语言模型提取照片中的类别、颜色、可见品牌和特征，再结合用户填写的信息对相反类型记录排序，并展示前五个候选及匹配依据。

本研究拟比较三种排序方法：只使用用户填写信息的表单基线、加入照片视觉属性的方法，以及再对前五个候选做照片直接比较的方法。研究计划建立经同意、匿名化并人工标注的配对数据集，暂建议以 Hit Rate@5 为唯一主要效果指标，以 Recall@5 和 MRR@5 为次要指标，并记录响应时间、模型失败率及实际调用费用。该指标方案尚待导师确认。若经导师与学校批准，可增加小规模易用性评估。系统的分数只用于排序提示，不作为物品所有权证明。

## 问题陈述

失物和拾获信息可能分散在公告板、聊天群或其他渠道中，失主与拾获者需要人工查找相似记录。简单按类别、地点或时间筛选，可能无法充分利用照片中可见的颜色、品牌和独特特征；但仅凭视觉相似也可能把外观相近的不同物品误配。需要研究一种把照片属性与用户填写的类别、颜色、地点、时间和说明结合起来的排序方式，并评估它是否能改善候选排序。

**相关工作边界：** Dhanawardhana et al. (2025) 已实现 SBERT 文字相似、Siamese 图片相似及地点/时间融合的失物 PWA（[出版方全文](https://www.oajaiml.com/uploads/archivepdf/299052212.pdf)）。全文称文字描述由模板脚本生成，融合样本仅 170 条且时间相似度随机模拟；其指标是配对分类而非固定候选池 Top-K 排序，且结果章节数字不一致。因此不能把“做 AI 失物网站”“首次融合照片与时空信息”作为创新主张。其他相关系统包括 [IEEE IRCE 2025](https://ieeexplore.ieee.org/document/11203217/)、[IEEE MEDCOM 2025](https://ieeexplore.ieee.org/document/11405255/) 和 [IEEE ICHORA 2026](https://ieeexplore.ieee.org/abstract/document/11537024)。本项目的候选研究问题是：在同一、按物品身份隔离且有可靠标签的候选池上，DeepSeek 视觉属性与候选照片直接比较是否改善 Top-K 排序，以及带来多少 API 成本/时延。这个比较方向仍须系统检索全文并经导师确认，不能声称已证明新颖。

## 研究问题

**研究问题（草案，待导师确认）：**

- **RQ1：** 在相同的已标注查询和候选集合上，加入照片提取的结构化视觉属性，相较只使用表单信息，是否能提高 Hit Rate@5？
- **RQ2：** 在视觉属性排序的候选初筛后加入候选照片直接比较，相较视觉属性方法是否能进一步提高 Hit Rate@5？

Recall@5 与 MRR@5 作为预先指定的次要指标；另记录视觉方法的响应时间、调用失败率和实际费用。将 RQ1 与 RQ2 分开，可分别衡量属性提取和照片比较的增量。此主指标建议及多重比较处理仍需导师确认，并须在查看 test 结果前冻结。

## 研究目标

1. 设计并实现手机浏览器可用的失物记录发布、候选检索和排序原型。
2. 实现表单信息基线、视觉属性和候选照片比较排序方法，并提供可复现的离线比较工具。
3. 在经同意并人工标注的数据上比较排序指标、运行时间、失败率和实际模型费用。

## 范围

### 包含

- 发布“丢失”或“拾获”记录。
- 填写物品类别、颜色、粗略地点、大概时间和说明，并上传照片。
- 可选调用 DeepSeek 视觉 API 提取物品类别、颜色、可见品牌和特征。
- 对相反类型记录排序，展示最多五条候选及简短匹配依据。
- 用户注册、登录及管理自己的记录；访客可浏览公开记录。
- Vercel 公网演示部署；Neon PostgreSQL 保存记录，Vercel Blob 保存图片，Neon Auth 管理账号。
- 记录按 90 天期限自动清理；图片重新编码以移除 EXIF 元数据。
- 研究比较表单基线、视觉属性排序，以及对属性排序前五名做候选照片比较后的排序。
- 网页适配手机和电脑浏览器。

### 当前不包含

- 原生 Android/iOS 应用、即时聊天、认领验证和管理员审核。
- 人脸识别、物品所有权自动判定或“匹配成功”的自动结论。
- 自动向用户发送通知，以及专门的反滥用/登录尝试限流机制。

目前应用已公开部署，但公开演示不代表已完成学校伦理审批或适合处理未经许可的真实个人数据。研究范围、数据处理和参与者安排仍应按导师及学校要求确认。

## 系统设计

- **前端：** 原生 HTML、CSS、JavaScript，作为响应式网页运行。
- **后端：** Python + FastAPI，负责表单验证、图片处理、视觉 API 调用和匹配排序。
- **存储：** 本地开发使用 SQLite 和本地图片目录；公开部署使用 Neon PostgreSQL 保存记录、Vercel Blob 保存图片。上传图片重新编码以移除 EXIF 元数据。
- **视觉分析：** 仅当发布者对该条记录明确勾选 AI 处理同意且配置 API 密钥时，才在发布时调用 DeepSeek；未同意、未配置或调用失败时，仍可使用表单信息排序。照片直接比较还要求候选记录发布者也已同意。
- **匹配：** 先限定到相反方向的记录，再用启发式分数排序；分数为排序参考，不是概率。
- **账号和记录权限：** Neon Auth 管理登录；新增、关闭和删除记录需要登录，并按发布者 ID 限定管理权限。公开记录及照片可被访客浏览。
- **当前限制：** 暂无认领验证、管理员审核、私有图片访问或应用自定义登录限流；公开演示仍可能被滥用，不能当作经过完整安全认证的商业服务。

详细数据流见 [`SYSTEM_ARCHITECTURE.md`](SYSTEM_ARCHITECTURE.md)，当前评分规则见 [`MATCHING_ALGORITHM.md`](MATCHING_ALGORITHM.md)。

## 研究方法

### 对比方法

1. **表单基线：** 使用用户填写的类别、颜色、地点、时间和说明。
2. **视觉属性方法：** 使用相同的表单信息，再加入照片分析得到的类别、颜色、品牌和特征。
3. **候选照片比较方法：** 先按第二种方法取前五名，再将线上已使用的 45% 属性分数与 55% 照片直接比较分数合并排序。

三种方法应处理完全相同的查询、候选集合和人工标签。离线工具从 `photo_scores.csv` 读取在批准流程下预先生成的模型照片比较分数；它本身不调用 API。排序权重只用 development 集调整；最终 test 集不用于调参或改提示词。该第三种方法在脚本中已有入口，但尚未用研究数据运行或验证。

### 数据集

- 使用经同意拍摄或取得授权的普通物品照片，不收集不必要的个人资料。
- 每个查询应有人工确认的“同一件实物”正例和已确认的负例；应包含类别/颜色相近但不是同一实物的困难负例。不确定配对单独标记，不自动视为负例。
- 按物品身份分组划分 development/test，避免同一实物的照片或重复记录跨集合。
- 样本量、数据来源、标注人数和统计方案待导师确认。
- 未经学校许可，不把真实研究图片发送给第三方视觉 API，也不将真实数据提交到公开代码仓库。

数据字段和标注流程草案见 [`DATASET_AND_ANNOTATION_GUIDE.md`](DATASET_AND_ANNOTATION_GUIDE.md)。

### 指标

- **Hit Rate@5（建议唯一主要指标，待导师确认）：** 每条查询是否至少有一个正确配对出现在前五名，再对查询取平均。
- **Recall@5（次要指标）：** 每条查询的已标注正例中有多少进入前五名，再对查询取宏平均。
- **MRR@5（次要指标）：** 第一条正确配对排名的倒数；前五名没有正确配对则为 0，再对查询取平均。
- **方法差异：** 报告按物品组配对 cluster bootstrap 得到的 95% 置信区间；物品组数量少时谨慎解释。
- **运行指标：** 响应时间、视觉 API 调用失败率及实际单条费用。
- **可选易用性评估：** 获得导师和学校批准后，再招募参与者完成发布与查看候选任务。

离线脚本可输出总体指标和逐候选名次，见根目录 `README.md` 的运行说明。

## 风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| 外观相似导致误配 | 展示匹配依据与不确定性，由用户判断；不自动认定所有权。 |
| 配对标签不完整或有分歧 | 预先制定标注指南；双人标注部分样本；记录 uncertain。 |
| 图片包含个人信息 | 收集前检查图片、移除 EXIF、限制访问并按期删除。 |
| 第三方 API 处理数据 | 先确认学校批准和服务条款；保留无需 API 的基线。 |
| 权重或模型调整造成测试集泄漏 | 只用 development 集调整；冻结测试集标签与提示词版本。 |
| API 延迟或费用变化 | 记录实际模型、失败、响应时间和用量；减少重复调用。 |
| 演示原型被误当成已批准的真实服务 | 页面说明公开范围和 AI 图片处理；真实研究数据上线前按导师/学校流程审批并限制数据用途。 |
